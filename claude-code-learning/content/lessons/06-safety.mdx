# 6. 안전하게 쓰기 (권한·되돌리기)

## 📌 이 페이지에서 배울 것
- 권한 모드 4가지와 언제 어떤 모드를 쓸지
- 허용·차단 규칙을 정하는 법
- 실수했을 때 되돌리는 법과 그 한계
- 비밀 정보를 지키는 법

⏱ 예상 시간: 30분

---

## 6-1. 왜 안전이 중요할까?

Claude Code는 내 컴퓨터에서 **파일을 만들고, 고치고, 지우고, 명령을 실행할 수 있습니다.** 아주 편리하지만, 잘못된 요청이나 실수 하나로 중요한 파일이 바뀌거나 사라질 수도 있습니다.

> 💡 비유: 집 열쇠를 맡긴 도우미입니다. 믿을 만하지만, **어느 방까지 들어가도 되는지**는 내가 정해야 합니다.

---

## 6-2. 권한 모드 4가지

`Shift + Tab`을 누를 때마다 모드가 바뀌고, 입력창 아래 상태 표시줄에 지금 모드가 나옵니다.

| 모드 | 상태 표시줄 | 묻지 않고 하는 일 | 이럴 때 |
|---|---|---|---|
| **수동 (Manual)** | `⏸ manual mode on` | 파일 읽기만 | 처음 배울 때, 중요한 프로젝트 ⭐ |
| **수정 자동 허용** | `⏵⏵ accept edits on` | 읽기 + 파일 수정 + `mkdir`·`mv`·`cp` 같은 기본 파일 명령 | 결과를 나중에 한꺼번에 확인할 때 |
| **계획 (Plan)** | `⏸ plan mode on` | 읽기와 조사만. **코드는 안 고침** | 큰 작업 전에 계획 세울 때 (5장) |
| **자동 (Auto)** | `⏵⏵ auto mode on` | 거의 모든 일. 대신 안전 검사기가 위험한 작업을 막음 | 익숙해진 뒤, 방향이 확실한 긴 작업 |

**순서**: 자동 → 수동 → 수정 자동 허용 → 계획 → 다시 자동

> 💡 최신 버전은 **자동 모드로 시작**합니다. 처음 배울 때는 `Shift + Tab`으로 **수동 모드**로 바꾸는 것을 추천합니다.

### 자동 모드를 쓸 때 알아 둘 것
- 별도의 **안전 검사기**가 내 요청을 벗어나거나 위험해 보이는 작업을 막습니다. 하지만 **완벽한 안전장치는 아닙니다.**
- 대화에서 **"푸시하지 마"**, **"배포 전에 나한테 확인받아"**처럼 말하면 검사기가 그 경계를 지키려고 합니다.
- 다만 대화가 길어져 요약(`/compact`)되면 그 말이 사라질 수 있습니다. **반드시 지켜야 하는 것은 6-3의 차단 규칙**으로 정하세요.

> ⚠️ `bypassPermissions`(모든 확인 건너뛰기)라는 모드도 있지만, **격리된 테스트 환경 전용**입니다. 초보자는 쓰지 마세요.

---

## 6-3. 허용·차단 규칙 정하기: `/permissions`

자주 쓰는 안전한 명령은 **매번 묻지 않게**, 위험한 일은 **아예 못 하게** 정할 수 있습니다.

```text
/permissions
```

| 규칙 | 뜻 | 예시 |
|---|---|---|
| **Allow** (허용) | 묻지 않고 실행 | `npm run`으로 시작하는 명령 |
| **Ask** (확인) | 항상 물어봄 | `git push` |
| **Deny** (차단) | 절대 못 함 | `.env` 파일 읽기 |

**우선순위**: 차단 → 확인 → 허용 순서로 검사합니다. **차단 규칙은 어떤 모드에서도 이깁니다.**

### 설정 파일로 정하기
규칙은 `.claude/settings.json` 파일에 저장됩니다. Claude에게 말로 시켜도 됩니다.

```json
{
  "permissions": {
    "allow": ["Bash(npm run *)"],
    "ask": ["Bash(git push *)"],
    "deny": ["Read(./.env)", "Read(./secrets/**)"]
  }
}
```

| 규칙 | 뜻 |
|---|---|
| `Bash(npm run *)` | `npm run build`, `npm run test` 등 `npm run`으로 시작하는 명령 |
| `Bash(git push *)` | `git push`로 시작하는 명령 |
| `Read(./.env)` | 현재 폴더의 `.env` 파일 읽기 |
| `Read(./secrets/**)` | `secrets` 폴더 안의 모든 파일 읽기 |

### 💻 따라 하기
```text
/update-config .env 파일은 절대 읽지 못하게 하고, git push는 항상 나한테 물어보게 설정해 줘
```

> 💡 수동 모드에서 **"Yes, and don't ask again"**을 고르면, 그 허용 규칙이 `.claude/settings.local.json`에 자동으로 저장됩니다. 나중에 `/permissions`에서 확인하고 지울 수 있습니다.

## 6-4. 되돌리기: `/rewind` 자세히

`/rewind`를 입력하거나 **빈 입력창에서 `Esc`를 두 번** 누르면 되돌리기 메뉴가 열립니다. 내가 보냈던 메시지 목록에서 시점을 고른 뒤, 할 일을 선택합니다.

| 선택 | 뜻 |
|---|---|
| **Restore code and conversation** | 코드와 대화 모두 그 시점으로 |
| **Restore conversation** | 대화만 되돌리고 코드는 그대로 |
| **Restore code** | 코드만 되돌리고 대화는 그대로 |
| **Summarize from here** | 그 시점 이후 대화를 요약해서 공간 확보 |
| **Never mind** | 취소 |

### ⚠️ 되돌리기의 한계
`/rewind`는 Claude가 **파일 편집 기능으로 직접 고친 파일**만 되돌립니다. 아래는 되돌리지 **못합니다.**

| 되돌릴 수 없는 것 | 예시 |
|---|---|
| Claude가 **터미널 명령**으로 바꾼 파일 | `rm`으로 지운 파일, `mv`로 옮긴 파일 |
| 내가 **직접** 고친 파일 | 메모장으로 고친 내용 |
| 외부에 보낸 것 | GitHub에 푸시한 것, 보낸 메시지 |

그리고 되돌리기 기록은 **약 30일 뒤 자동으로 지워집니다.**

> 💡 **진짜 안전망은 Git입니다.** 중요한 작업 전에 "지금 상태를 커밋해 줘"라고 하세요. Git 커밋은 지워지지 않고 언제든 돌아갈 수 있습니다. (7장)

## 6-5. `/diff`로 확인하는 습관

Claude가 무엇을 바꿨는지 **한눈에** 볼 수 있습니다.

```text
/diff
```

**작업이 끝날 때마다** 확인하세요.
- 요청하지 않은 파일이 바뀌지 않았는지
- 지워지면 안 되는 내용이 지워지지 않았는지
- 비밀 정보가 코드에 들어가지 않았는지

---

## 6-6. 비밀 정보 지키기

**API 키, 비밀번호, 토큰**은 코드에 직접 쓰면 안 됩니다. GitHub에 올라가면 전 세계 누구나 볼 수 있습니다.

### 올바른 방법: `.env` 파일
**① 비밀 정보는 `.env` 파일에 따로 둡니다**
```text
WEATHER_API_KEY=여기에_실제_키
```

**② `.gitignore`에 `.env`를 추가해서 GitHub에 올라가지 않게 합니다**
```text
.env
```

**③ 다른 사람을 위해 `.env.example`에 이름만 적어 둡니다**
```text
WEATHER_API_KEY=
```

**④ Claude가 `.env`를 읽지 못하게 차단 규칙을 추가합니다** (6-3)

### 💻 따라 하기
```text
이 프로젝트에 .gitignore를 만들고 .env를 추가해 줘. .env.example도 만들어 줘.
```

> ⚠️ **채팅창에 API 키를 붙여 넣지 마세요.** 대화 기록에 남습니다. `.env` 파일에 직접 입력하세요.

## 6-7. 조심해야 할 요청

이런 요청은 실행 전에 **한 번 더 생각**하고, 수동 모드나 계획 모드로 하세요.

| 위험한 요청 | 왜 위험한가 | 더 안전한 방법 |
|---|---|---|
| "필요 없는 파일 다 지워 줘" | 필요한 파일까지 지울 수 있음 | "지울 후보 목록만 먼저 보여 줘" |
| "인터넷에서 찾은 이 스크립트 실행해 줘" | 무슨 일을 할지 모름 | "이 스크립트가 무슨 일을 하는지 먼저 설명해 줘" |
| "다른 폴더의 파일도 고쳐 줘" | 작업 폴더 밖까지 영향 | 그 폴더에서 따로 `claude` 실행 |
| "에러 안 나게 아무렇게나 고쳐 줘" | 문제를 숨기기만 할 수 있음 | "원인을 먼저 설명하고 고쳐 줘" |
| "강제로 푸시해 줘" | 다른 사람의 작업이 사라질 수 있음 | 7장의 방법으로 차근차근 |

### 모르는 폴더를 열 때
다른 사람에게 받은 프로젝트에는 Claude가 따르는 설정 파일(`CLAUDE.md`, `.claude/`)이 들어 있을 수 있습니다. 처음 실행할 때 **이 폴더를 믿을지** 물어보면, 출처를 알 때만 허용하세요.

## ✅ 확인하기
- [ ] `Shift + Tab`으로 4가지 모드를 모두 바꿔 봤다
- [ ] `/permissions`를 열어 규칙 목록을 확인했다
- [ ] `.env` 읽기 차단 규칙을 추가했다
- [ ] `/rewind`로 코드만 되돌려 봤다
- [ ] 작업 후 `/diff`로 변경 내용을 확인했다
- [ ] `.gitignore`에 `.env`를 추가했다

## ⚠️ 자주 하는 실수
- **자동 모드면 무조건 안전하다고 믿기**: 검사기는 도움이 되지만 완벽하지 않습니다. 중요한 작업은 확인하세요.
- **`/rewind`만 믿기**: 터미널 명령으로 지운 파일은 돌아오지 않습니다. Git 커밋을 함께 쓰세요.
- **"Yes, and don't ask again"을 습관적으로 누르기**: 무엇을 영구 허용하는지 읽고 누르세요.
- **API 키를 코드나 채팅에 붙여 넣기**: 반드시 `.env`에.
