# 5. 잘 시키는 법 (프롬프트)

## 📌 이 페이지에서 배울 것
- 원하는 결과를 얻는 요청의 5가지 원칙
- 계획 모드로 "먼저 계획, 나중에 실행"하기
- 에러가 나거나 결과가 마음에 안 들 때 대처법

⏱ 예상 시간: 30분

---

## 5-1. 왜 요청 방법이 중요할까?

Claude는 **내 머릿속을 볼 수 없습니다.** "예쁘게 만들어 줘"라고 하면, Claude가 생각하는 "예쁨"으로 만듭니다.

> 💡 비유: 처음 만난 인테리어 기사님에게 "집 좀 예쁘게 해 주세요"라고 하는 것과 "거실 벽을 연한 회색으로 칠하고, 소파 위에 선반 하나 달아 주세요"라고 하는 것의 차이입니다.

---

## 5-2. 5가지 원칙

### ① 구체적으로
무엇을, 어디에, 어떻게를 말합니다.
- ❌ "버튼 추가해 줘"
- ✅ "`hello.html` 제목 아래에 '연락하기' 버튼을 추가하고, 누르면 내 이메일로 메일 쓰기 창이 열리게 해 줘"

### ② 작게 나눠서
큰 일은 단계로 나눠서 하나씩 시킵니다. 한 단계가 잘 되는지 확인하고 다음으로 갑니다.
- ❌ "쇼핑몰 만들어 줘"
- ✅ "먼저 상품 5개를 카드 모양으로 보여 주는 목록 페이지만 만들어 줘. 장바구니는 다음에 할게"

### ③ 목표와 조건을 함께
왜 필요한지, 지켜야 할 것은 무엇인지 알려 줍니다.
- ❌ "로그인 기능 만들어 줘"
- ✅ "가족끼리만 쓰는 메모 앱이라 복잡한 회원가입은 필요 없어. 비밀번호 하나만 입력하면 들어가지게 해 줘. 새 라이브러리는 쓰지 마"

### ④ 예시 보여 주기
말로 설명하기 어려우면 예시를 줍니다. 원하는 모양의 **스크린샷을 붙여 넣는 것**도 좋은 방법입니다.
- ✅ "날짜는 `2026년 10월 12일 (일)`처럼 보여 줘"
- ✅ `[이미지]` "이 사이트처럼 위쪽에 메뉴 막대를 만들어 줘"

### ⑤ 확인 방법 알려 주기
"다 됐어요"가 아니라 **진짜 되는지** 확인하게 합니다.
- ✅ "다 만들면 브라우저에서 열어서 버튼이 잘 동작하는지 확인해 줘"
- ✅ "고친 뒤에 `npm test`를 실행해서 모두 통과하는지 확인해 줘"

## 5-3. 나쁜 요청 vs 좋은 요청 10쌍

| | ❌ 나쁜 요청 | ✅ 좋은 요청 |
|---|---|---|
| 1 | 앱 만들어 줘 | 할 일을 추가·삭제할 수 있는 웹페이지를 HTML 파일 하나로 만들어 줘 |
| 2 | 예쁘게 해 줘 | 배경은 흰색, 글자는 진한 회색, 버튼은 둥근 모서리의 파란색으로 해 줘 |
| 3 | 이거 고쳐 줘 | `@app.js` 저장 버튼을 눌러도 목록에 안 나타나. 원인을 찾아서 고쳐 줘 |
| 4 | 에러 나 | (에러 메시지를 그대로 붙여 넣고) 이 에러가 나. 원인을 설명하고 고쳐 줘 |
| 5 | 더 좋게 만들어 줘 | 목록이 100개 넘으면 느려져. 한 번에 20개씩 보이게 바꿔 줘 |
| 6 | 코드 정리해 줘 | `@app.js`에서 같은 코드가 반복되는 부분을 함수 하나로 합쳐 줘. 동작은 바꾸지 마 |
| 7 | 모바일도 되게 | 폰 화면(가로 400px)에서도 글자가 잘리지 않게 해 줘 |
| 8 | 테스트 해 줘 | 할 일 추가 기능에 대한 테스트를 만들고 실행해서 결과를 알려 줘 |
| 9 | 이 코드 뭐야? | `@app.js`가 하는 일을 초보자가 이해할 수 있게 순서대로 설명해 줘 |
| 10 | 다 알아서 해 | 먼저 어떻게 만들지 계획만 보여 줘. 내가 확인한 뒤에 시작해 |

## 5-4. 계획 모드: 먼저 계획, 나중에 실행

큰 작업은 바로 시키지 말고 **계획부터 보세요.** 계획 모드에서는 Claude가 파일을 읽고 조사만 하고, **코드는 고치지 않습니다.**

### 계획 모드 쓰는 법
**방법 1**: 요청 앞에 `/plan`을 붙입니다.
```text
/plan 할 일 목록에 마감 날짜 기능을 추가하고 싶어
```

**방법 2**: `Shift + Tab`을 눌러 상태 표시줄이 `⏸ plan mode on`이 될 때까지 바꾼 뒤 요청합니다.

### 계획이 나오면
Claude가 계획을 보여 주고 어떻게 할지 묻습니다.

| 선택 | 뜻 |
|---|---|
| **Yes, and use auto mode** | 계획대로 진행. 묻지 않고 자동으로 작업 |
| **Yes, manually approve edits** | 계획대로 진행. 파일을 고칠 때마다 확인 |
| **No, keep planning** | 계획 수정. 바꾸고 싶은 점을 말해 줌 |

> 💡 초보자에게는 **Yes, manually approve edits**를 추천합니다. 계획과 실제 작업을 하나씩 비교하며 배울 수 있습니다.

> 💡 `Ctrl + G`를 누르면 계획을 편집기로 열어서 직접 고칠 수도 있습니다.

### 💻 따라 하기
```text
/plan hello.html에 다크 모드 전환 버튼을 넣고 싶어. 어떻게 할지 계획을 보여 줘.
```
계획을 읽어 보고, 마음에 안 드는 부분이 있으면 **No, keep planning**을 고른 뒤 고칠 점을 말해 보세요.

## 5-5. 에러가 났을 때

**에러 메시지를 요약하지 말고 그대로 붙여 넣으세요.** Claude에게는 에러 메시지 전체가 중요한 단서입니다.

```text
브라우저에서 버튼을 누르면 아무 반응이 없고, 개발자 도구 콘솔에 이렇게 나와.

Uncaught TypeError: Cannot read properties of null (reading 'addEventListener')
    at app.js:12

원인을 설명하고 고쳐 줘.
```

**잘 알려 주는 3가지**
1. **무엇을 했는지**: "저장 버튼을 눌렀더니"
2. **무엇을 기대했는지**: "목록에 추가될 줄 알았는데"
3. **실제로 무슨 일이 있었는지**: "아무 일도 안 일어나고 콘솔에 이 에러가 나와"

> 💡 브라우저 개발자 도구는 `F12`(macOS는 `Cmd + Option + I`)로 열고, **Console** 탭에서 에러를 볼 수 있습니다.

## 5-6. 결과가 마음에 안 들 때

| 상황 | 이렇게 하세요 |
|---|---|
| 조금 아쉬움 | 바꿀 점만 구체적으로 다시 요청: "버튼 색만 초록색으로" |
| 방향이 완전히 틀림 | `Esc`로 멈추고 `/rewind`로 되돌린 뒤, 더 구체적으로 다시 요청 |
| 같은 실수를 반복함 | 그 규칙을 **CLAUDE.md에 추가** (4장) |
| 대화가 꼬임 | `/clear`로 새로 시작하고, 지금까지 정한 내용을 정리해서 다시 요청 |
| 내가 뭘 원하는지 모르겠음 | "선택지 3가지를 보여 줘. 각각 장단점도 알려 줘" |

### 질문을 시켜 보세요
요구사항이 애매하면, Claude에게 **먼저 질문하라고** 할 수 있습니다.
```text
가계부 앱을 만들고 싶어. 시작하기 전에 나한테 필요한 질문을 5개만 해 줘.
```

## ✅ 확인하기
- [ ] 나쁜 요청 하나를 5원칙에 맞게 고쳐 써 봤다
- [ ] `/plan`으로 계획을 받아 보고, 한 번은 **No, keep planning**으로 고쳐 봤다
- [ ] 에러 메시지를 그대로 붙여 넣어 고쳐 달라고 해 봤다
- [ ] "먼저 질문해 줘"로 요구사항을 정리해 봤다

## ⚠️ 자주 하는 실수
- **한 번에 너무 많이 시키기**: 결과가 엉키고 확인하기 어렵습니다. 하나씩!
- **에러를 요약해서 말하기**: "뭔가 에러 나"보다 메시지 전체를 붙여 넣으세요.
- **결과를 확인하지 않고 다음으로 넘어가기**: 단계마다 직접 열어서 확인하세요.
- **같은 말을 계속 반복하기**: 세 번째쯤 같은 요청을 하고 있다면 `/clear` 후 처음부터 정리해서 요청하세요.
