# 3. 기본 사용법

## 📌 이 페이지에서 배울 것
- 질문하기와 작업 시키기의 차이
- 파일 지정, 멈추기, 되돌리기 등 매일 쓰는 조작
- 대화가 길어졌을 때 관리하는 법

⏱ 예상 시간: 25분

> 🛠 준비: 2장에서 만든 `my-first-project` 폴더에서 `claude`를 실행해 두세요.

---

## 3-1. 질문하기 vs 작업 시키기

Claude Code에게 하는 말은 크게 두 종류입니다.

| 종류 | 예시 | Claude가 하는 일 |
|---|---|---|
| **질문** | "hello.html이 어떻게 동작하는지 설명해 줘" | 파일을 읽고 설명만 함. 아무것도 바꾸지 않음 |
| **작업** | "hello.html에 버튼을 하나 추가해 줘" | 파일을 고침. 수동 모드라면 바꾸기 전에 허락을 구함 |

> 💡 처음 보는 코드라면 **질문 먼저, 작업은 나중에** 하세요. "이 프로젝트 구조를 설명해 줘"는 언제나 좋은 첫 질문입니다.

### 💻 따라 하기
```text
이 폴더에 어떤 파일이 있고, 각각 무슨 역할인지 설명해 줘.
```

---

## 3-2. 입력창에서 쓰는 특수 기호 3가지

입력창 **맨 앞**이나 문장 안에 아래 기호를 쓰면 특별한 기능이 동작합니다.

| 기호 | 기능 | 예시 |
|---|---|---|
| `@` | **파일 지정**. 입력하면 파일 목록이 뜨고 `Tab`으로 고름 | `@hello.html 이 파일의 글자 색을 바꿔 줘` |
| `/` | **명령어**. 맨 앞에 입력 | `/help` |
| `!` | **터미널 명령 바로 실행**. 맨 앞에 입력. 결과를 Claude도 봄 | `!ls` |

> 💡 `@`로 파일을 지정하면 Claude가 어떤 파일을 말하는지 헷갈리지 않아서 결과가 더 정확해집니다.

### 💻 따라 하기
```text
@hello.html 이 파일에 "더 알아보기" 버튼을 추가하고, 누르면 "반가워요!" 알림이 뜨게 해 줘.
```

---

## 3-3. 꼭 외울 단축키

| 단축키 | 기능 | 언제 쓰나 |
|---|---|---|
| `Esc` | **Claude 멈추기** | 엉뚱한 방향으로 갈 때. 지금까지 한 작업은 남음 |
| `Esc` 두 번 (입력창이 비어 있을 때) | **되돌리기 메뉴** 열기 | 이전 시점으로 코드나 대화를 되돌릴 때 |
| `Shift + Tab` | **권한 모드 바꾸기** | 6장에서 자세히 |
| `↑` | 이전에 입력한 내용 불러오기 | 같은 요청을 조금 바꿔 다시 보낼 때 |
| `Ctrl + C` | 작업 중단. 아무것도 없을 때 두 번 누르면 종료 | |
| `?` (입력창이 비어 있을 때) | 단축키 도움말 보기 | 단축키가 기억나지 않을 때 |

### 여러 줄 입력하기
Enter를 누르면 바로 전송됩니다. 줄을 바꾸고 싶으면:
- **`\`를 입력하고 Enter** — 모든 터미널에서 동작
- **`Ctrl + J`** — 모든 터미널에서 동작
- **`Shift + Enter`** — Windows Terminal, macOS 터미널 등에서 바로 동작. 안 되면 `/terminal-setup`

### 이미지 붙여 넣기
화면 캡처를 복사한 뒤 입력창에서 붙여 넣으면 이미지를 보여 줄 수 있습니다.
- macOS: `Ctrl + V` (iTerm2는 `Cmd + V`)
- Windows: `Alt + V`

```text
[이미지] 이 디자인처럼 hello.html을 바꿔 줘.
```

## 3-4. 작업 중에 말 걸기

Claude가 작업하는 중에도 메시지를 입력할 수 있습니다. 보낸 메시지는 **대기열에 들어갔다가** Claude가 이어서 읽습니다.

- 방향을 살짝 바꾸고 싶을 때: 그냥 입력해서 보내기
- 완전히 잘못 가고 있을 때: `Esc`로 멈추고 다시 설명하기

---

## 3-5. 되돌리기: `/rewind`

Claude가 코드를 마음에 안 들게 바꿨다면 걱정하지 마세요.

1. `/rewind` 입력 (또는 빈 입력창에서 `Esc` 두 번)
2. 돌아가고 싶은 시점의 내 메시지를 고르기
3. **코드만, 대화만, 또는 둘 다** 되돌릴지 선택

> ⚠️ `/rewind`는 Claude가 **파일을 직접 고친 것**을 되돌립니다. Claude가 실행한 터미널 명령의 결과(예: 설치한 프로그램, 지운 파일)까지 모두 되돌리지는 못할 수 있습니다. 중요한 작업 전에는 7장에서 배울 **Git 커밋**으로 저장해 두세요.

---

## 3-6. 대화 관리하기

Claude는 대화 내용을 **작업 공간(컨텍스트)**에 담아 두고 기억합니다. 이 공간에는 한계가 있어서, 대화가 길어지면 앞 내용을 놓치거나 느려질 수 있습니다.

| 명령어 | 비유 | 언제 쓰나 |
|---|---|---|
| `/context` | 공책이 얼마나 찼는지 보기 | 느려졌다고 느낄 때 |
| `/compact` | 앞부분을 **요약 메모로 바꾸고 계속 쓰기** | 같은 작업을 계속하는데 대화가 길어졌을 때 |
| `/clear` | **새 공책으로 바꾸기** | 전혀 다른 작업을 시작할 때 |
| `/resume` | 예전 공책 다시 펼치기 | 어제 하던 대화를 이어 할 때 |

```text
/compact 버튼 기능 작업 내용 위주로 남겨줘
```

> 💡 **좋은 습관**: 작업 하나가 끝나면 `/clear`. 대화가 깨끗할수록 Claude가 더 정확합니다. 프로젝트 규칙은 4장의 `CLAUDE.md`에 적어 두면 `/clear` 후에도 사라지지 않습니다.

## 3-7. 모델과 사용량

| 명령어 | 기능 |
|---|---|
| `/model` | AI 모델 고르기. 더 강한 모델은 어려운 일에 좋지만 사용량을 더 씁니다 |
| `/effort` | 얼마나 깊이 생각할지 정하기 (`low` ~ `max`, `auto`) |
| `/usage` | 지금까지의 사용량과 요금제 한도 보기 |

> 💡 처음에는 **기본 설정 그대로** 써도 충분합니다. 결과가 아쉬울 때 바꿔 보세요.

## ✅ 확인하기
- [ ] `@`로 파일을 지정해서 요청해 봤다
- [ ] `!ls`로 터미널 명령을 바로 실행해 봤다
- [ ] Claude가 작업 중일 때 `Esc`로 멈춰 봤다
- [ ] `/rewind`로 변경을 되돌려 봤다
- [ ] `/context`로 공간이 얼마나 찼는지 확인하고 `/clear`로 새로 시작해 봤다

## ⚠️ 자주 하는 실수
- **한 대화에서 모든 일을 하기**: 대화가 길어질수록 정확도가 떨어집니다. 작업 단위로 `/clear` 하세요.
- **`/clear`하면 규칙도 사라진다고 착각하기**: `CLAUDE.md`에 적은 내용은 매번 다시 읽습니다.
- **`Esc`가 모든 것을 취소한다고 생각하기**: `Esc`는 멈추기만 합니다. 이미 바뀐 파일은 `/rewind`로 되돌리세요.

## 🧠 퀴즈
1. 다른 작업을 새로 시작할 때 쓰는 명령어는?
   - (가) `/compact`  (나) `/clear`  (다) `/model`
2. 특정 파일을 지정해서 요청할 때 쓰는 기호는?
   - (가) `@`  (나) `!`  (다) `#`
3. Claude가 고친 코드를 이전 상태로 되돌리려면?
   - (가) `Esc` 한 번  (나) `/rewind`  (다) `/usage`

<details>
<summary>정답 보기</summary>

1. (나) — `/compact`는 요약해서 같은 대화를 이어 갑니다.
2. (가) — `!`는 터미널 명령 실행입니다.
3. (나) — `Esc`는 멈추기만 합니다.
