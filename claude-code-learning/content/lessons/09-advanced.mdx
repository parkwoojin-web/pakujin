## 9-1. Skills: 나만의 `/명령어`

자주 하는 요청을 **명령어로 등록**합니다.

### 만드는 법
`.claude/skills/커밋정리/SKILL.md` 파일을 만들고:
```markdown
---
description: 변경 사항을 확인하고 한국어 커밋 메시지로 커밋한다
---
1. 바뀐 파일과 내용을 확인한다.
2. `feat:`, `fix:`, `docs:` 중 알맞은 말머리로 한국어 커밋 메시지를 만든다.
3. 커밋하고, 무엇을 커밋했는지 3줄로 알려 준다.
```

이제 `/커밋정리`라고 입력하면 이 순서대로 실행됩니다.

| 위치 | 쓸 수 있는 곳 |
|---|---|
| `.claude/skills/` | 이 프로젝트에서만 |
| `~/.claude/skills/` | 내 모든 프로젝트에서 |

> 💡 `description`이 내 요청과 맞으면 Claude가 **알아서** 이 Skill을 쓰기도 합니다. `/skills`로 목록을 볼 수 있습니다.

> 💡 말로 만들어 달라고 해도 됩니다: "커밋 메시지를 정리해서 커밋하는 Skill을 만들어 줘"

## 9-2. 서브에이전트: 역할을 맡은 보조 Claude

특정 일만 전문으로 하는 **보조 Claude**를 만듭니다. 서브에이전트는 **자기만의 대화 공간**에서 일하고 결과만 돌려주므로, 메인 대화가 복잡해지지 않습니다.

### 만드는 법
`.claude/agents/code-reviewer.md`:
```markdown
---
name: code-reviewer
description: 코드를 검토해서 버그와 개선점을 찾는다
tools: Read, Glob, Grep
---

너는 꼼꼼한 코드 검토자다. 코드를 읽고 버그, 보안 문제, 개선점을
초보자도 이해할 수 있게 설명한다. 코드는 직접 고치지 않는다.
```

`tools`에 읽기 도구만 넣었기 때문에, 이 서브에이전트는 파일을 **읽기만** 하고 고치지 못합니다.

### 쓰는 법
```text
code-reviewer 서브에이전트로 최근 변경 사항을 검토해 줘.
```

## 9-3. MCP: 외부 서비스 연결

**MCP(Model Context Protocol)**는 Claude Code에 외부 서비스를 연결하는 표준 방법입니다. 연결하면 Claude가 그 서비스를 직접 읽고 쓸 수 있습니다.

### 연결하는 법 (터미널에서)
```bash
claude mcp add --transport http notion https://mcp.notion.com/mcp
```

| 명령 | 기능 |
|---|---|
| `claude mcp list` | 연결된 서버와 상태 보기 |
| `claude mcp remove 이름` | 연결 해제 |
| `/mcp` (Claude Code 안에서) | 상태 확인, 로그인, 관리 |

**적용 범위** (`--scope`)
- `local` (기본): 이 프로젝트에서 나만
- `project`: `.mcp.json`에 저장되어 팀과 공유
- `user`: 내 모든 프로젝트

> ⚠️ MCP 서버는 내 데이터에 접근할 수 있습니다. **믿을 수 있는 곳에서 만든 서버만** 연결하세요.

## 9-4. Hooks: 자동 실행 규칙

CLAUDE.md의 규칙은 Claude가 **참고**하는 것이라 가끔 놓칠 수 있습니다. **Hooks**는 정해진 순간에 **항상** 실행되는 명령입니다.

### 예시: 파일을 고칠 때마다 자동 정리
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }
        ]
      }
    ]
  }
}
```
Claude가 파일을 고치거나 만든 뒤(`PostToolUse`)마다, 그 파일을 Prettier로 자동 정리합니다.

### 자주 쓰는 순간
| 이름 | 언제 |
|---|---|
| `PreToolUse` | Claude가 도구를 쓰기 **전** (위험한 작업 막기) |
| `PostToolUse` | 도구를 쓴 **후** (자동 정리, 검사) |
| `Notification` | Claude가 내 입력을 기다릴 때 (알림 보내기) |

> 💡 JSON을 직접 쓰기 어려우면: `/update-config 파일을 고칠 때마다 prettier로 정리하는 hook을 만들어 줘`. 설정된 Hooks는 `/hooks`로 확인합니다.

## 9-5. 플러그인

Skills, 서브에이전트, Hooks, MCP 등을 **하나로 묶은 꾸러미**입니다. 남이 만든 플러그인을 설치하면 여러 기능이 한 번에 추가됩니다.

```text
/plugin
```
메뉴에서 플러그인을 찾아 설치하고, 켜고 끌 수 있습니다.

> ⚠️ 플러그인도 내 컴퓨터에서 명령을 실행할 수 있습니다. 출처를 확인하고 설치하세요.

## 9-7. 코드 검토 도구

| 명령 | 기능 |
|---|---|
| `/code-review` | 바뀐 코드에서 버그 찾기. `--fix`를 붙이면 바로 고침 |
| `/security-review` | 보안 문제 점검 |
| `/simplify` | 바뀐 코드를 더 깔끔하게 정리 |

> 💡 PR을 만들기 전에 `/code-review` → `/security-review` 순서로 점검하는 습관을 들이면 좋습니다.
