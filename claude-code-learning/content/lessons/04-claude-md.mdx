# 4. CLAUDE.md로 규칙 정하기

## 📌 이 페이지에서 배울 것
- CLAUDE.md가 무엇이고 왜 필요한지
- `/init`으로 자동으로 만들고 고치는 법
- 잘 쓴 규칙과 못 쓴 규칙의 차이

⏱ 예상 시간: 25분

---

## 4-1. CLAUDE.md란?

Claude Code는 **새 대화를 시작할 때마다 이전 대화를 기억하지 못합니다.** 그래서 "답은 한국어로 해 줘", "이 프로젝트는 이런 앱이야"를 매번 다시 말해야 합니다.

`CLAUDE.md`는 이 문제를 해결하는 **Claude용 안내문**입니다. 프로젝트 폴더에 이 파일을 두면, Claude가 **대화를 시작할 때마다 자동으로 읽습니다.**

> 💡 비유: 새로 온 아르바이트생에게 건네는 **업무 안내 쪽지**입니다. 매일 새로 오는 아르바이트생이라도 쪽지만 읽으면 바로 일할 수 있습니다.

### 이럴 때 CLAUDE.md에 적으세요
- Claude가 **같은 실수를 두 번** 했을 때
- 지난 대화에서 했던 설명을 **또 하고 있을 때**
- 새로 온 팀원에게도 꼭 알려 줄 내용일 때

---

## 4-2. `/init`으로 자동으로 만들기

직접 처음부터 쓰지 않아도 됩니다.

```text
/init
```

Claude가 프로젝트를 살펴보고 `CLAUDE.md` 초안을 만들어 줍니다. 실행 명령, 테스트 방법, 발견한 규칙 등이 들어갑니다. 이미 `CLAUDE.md`가 있으면 **덮어쓰지 않고 개선할 점을 제안**합니다.

만들어진 뒤에는 **Claude가 코드만 보고는 알 수 없는 내용**을 직접 덧붙이세요. 예를 들면 답변 언어, 만들려는 앱의 목적, 피하고 싶은 것 등입니다.

### 💻 따라 하기
1. `my-first-project`에서 `/init` 실행
2. 만들어진 `CLAUDE.md`를 열어 보기
3. 아래 내용을 추가해 달라고 요청하기
```text
CLAUDE.md에 다음 규칙을 추가해 줘.
- 설명과 답변은 한국어로 한다.
- 코딩 초보도 이해할 수 있게 쉽게 설명한다.
- 작업이 끝나면 무엇을 바꿨는지 3줄로 정리한다.
```

## 4-3. 무엇을 적을까? (기본 틀)

```markdown
# CLAUDE.md

## 프로젝트 개요
- 무엇을 만드는지 한두 줄
- 누가 쓰는지

## 기술 스택
- 언어, 프레임워크, 패키지 매니저

## 자주 쓰는 명령어
- 실행: npm run dev
- 테스트: npm test

## 규칙
- 지켜야 할 것들 (구체적으로)

## 커뮤니케이션
- 답변 언어, 설명 수준
```

> 📎 부록의 **CLAUDE.md 템플릿**을 복사해서 시작해도 됩니다.

---

## 4-4. 좋은 규칙 vs 나쁜 규칙

Claude는 CLAUDE.md를 **참고 자료**로 읽습니다. 그래서 **구체적이고 확인할 수 있는** 규칙일수록 잘 지킵니다.

| ❌ 나쁜 규칙 (애매함) | ✅ 좋은 규칙 (구체적) |
|---|---|
| 코드를 깔끔하게 짜 줘 | 들여쓰기는 스페이스 2칸 |
| 테스트를 잘 해 줘 | 커밋 전에 `npm test`를 실행 |
| 파일을 정리해서 둬 | 화면 컴포넌트는 `src/components/`에 둔다 |
| 친절하게 답해 줘 | 전문 용어는 처음 나올 때 한 줄로 설명한다 |
| 좋은 라이브러리를 써 | 새 라이브러리를 추가하기 전에 이유를 말하고 허락을 받는다 |

### 잘 쓰는 원칙
- **짧게**: 파일 하나에 **200줄 이하**를 권장합니다. 길수록 Claude가 덜 지킵니다.
- **제목과 목록으로 정리**: 긴 문단보다 `##` 제목과 `-` 목록이 읽기 쉽습니다.
- **서로 부딪히는 규칙 없애기**: "한국어로 답해"와 "영어로 답해"가 같이 있으면 Claude가 아무거나 고를 수 있습니다.

---

## 4-5. CLAUDE.md는 어디에 두나?

위치에 따라 적용 범위가 다릅니다.

| 위치 | 적용 범위 | 공유 | 이럴 때 |
|---|---|---|---|
| `~/.claude/CLAUDE.md` | **내 모든 프로젝트** | 나만 | "항상 한국어로 답해" 같은 나의 공통 취향 |
| `프로젝트/CLAUDE.md` | **이 프로젝트** | Git으로 팀과 공유 | 프로젝트 설명, 명령어, 규칙 |
| `프로젝트/CLAUDE.local.md` | 이 프로젝트, **나만** | 공유 안 함 (`.gitignore`에 추가) | 나만 쓰는 테스트 주소 등 |
| `프로젝트/하위폴더/CLAUDE.md` | 그 폴더 | Git으로 공유 | Claude가 그 폴더의 파일을 다룰 때 추가로 읽음 |

> 💡 `~`는 내 사용자 폴더입니다. Windows에서는 `C:\Users\내이름`, macOS에서는 `/Users/내이름`입니다.

**여러 파일이 있으면 모두 합쳐서 읽습니다.** 덮어쓰는 것이 아니라 차곡차곡 쌓입니다. 내가 작업하는 위치에 **가까운 파일일수록 나중에** 읽습니다.

## 4-6. CLAUDE.md 편집하고 확인하기

| 방법 | 설명 |
|---|---|
| `/memory` | CLAUDE.md 파일 목록을 보여 주고, 골라서 편집기로 열 수 있음 |
| 말로 요청 | "이 규칙을 CLAUDE.md에 추가해 줘" |
| 직접 편집 | 메모장이나 VS Code로 파일 열기 |
| `/context` | 지금 어떤 CLAUDE.md가 읽혔는지 확인 |

### 자동 메모리와의 차이
Claude에게 **"앞으로 npm 말고 pnpm을 써. 기억해 둬"**라고 말하면, Claude가 스스로 **자동 메모리**에 적어 둡니다.

| | CLAUDE.md | 자동 메모리 |
|---|---|---|
| 누가 쓰나 | **나** | **Claude** |
| 내용 | 규칙과 지시 | Claude가 배운 내 취향, 내가 고쳐 준 것 |
| 확인 | 파일을 직접 열어 봄 | `/memory`에서 자동 메모리 폴더 열기 |

> 💡 **꼭 지켜야 하는 규칙**은 "기억해 둬"보다 **"CLAUDE.md에 추가해 줘"**라고 요청하세요. 직접 보고 고칠 수 있어서 관리하기 쉽습니다.

---

## 4-7. 효과 확인 실험

CLAUDE.md가 정말 효과가 있는지 직접 확인해 봅시다.

1. CLAUDE.md에 이 규칙을 추가합니다.
   ```text
   - 모든 답변의 마지막 줄에 "🙂 오늘도 화이팅!"을 붙인다.
   ```
2. `/clear`로 대화를 새로 시작합니다.
3. 아무 질문이나 해 봅니다. 예: "hello.html 설명해 줘"
4. 마지막 줄에 문구가 붙었는지 확인합니다.
5. 확인했으면 이 규칙은 지워 주세요.

---

## ✅ 확인하기
- [ ] `/init`으로 CLAUDE.md를 만들었다
- [ ] 답변 언어와 설명 수준 규칙을 추가했다
- [ ] `/clear` 후에도 규칙이 적용되는 것을 확인했다
- [ ] 애매한 규칙 하나를 구체적인 규칙으로 바꿔 봤다

## ⚠️ 자주 하는 실수
- **너무 길게 쓰기**: 모든 것을 적으면 오히려 덜 지킵니다. 매번 꼭 필요한 것만 적으세요.
- **애매하게 쓰기**: "잘", "깔끔하게", "적당히"는 피하세요.
- **비밀 정보 적기**: CLAUDE.md는 Git으로 공유될 수 있습니다. 비밀번호, API 키는 절대 적지 마세요.
- **한 번 쓰고 잊기**: 프로젝트가 바뀌면 CLAUDE.md도 업데이트하세요. `/doctor prompt-audit`로 오래되거나 서로 부딪히는 규칙을 점검할 수 있습니다.

## 🧠 퀴즈

   - (가) `프로젝트/CLAUDE.md`  (나) `~/.claude/CLAUDE.md`  (다) `프로젝트/CLAUDE.local.md`
2. 다음 중 더 좋은 규칙은?
   - (가) "테스트를 잘 해 줘"  (나) "커밋 전에 `npm test`를 실행한다"
3. `/clear`를 하면 CLAUDE.md 규칙은?
   - (가) 사라진다  (나) 새 대화에서도 다시 읽는다
